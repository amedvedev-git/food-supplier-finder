# Поиск поставщиков для закупщика сети общепита

Прототип: **https://suppliers.alexmedvedev.com** · тестовое задание Goulash.tech (AI Generalist / AI Automation Specialist).

Закупщик выбирает сеть («Сушкоф и пицца» или «Жизньмарт»), категорию и город. Сервис показывает поставщиков из
открытых источников с рейтингом, ценой, минимальным заказом, доставкой, документами и проверкой юрлица. Отобранных
можно сравнить, добавить в шортлист со статусом и заметкой, отправить им письмо-запрос КП и выгрузить список в XLSX.

## Сценарий

1. **Поиск** — сеть → категория (одно дерево на обе сети, общие категории сравниваются напрямую) → город сети →
   география «местные · возят в город · все» (по умолчанию — кто работает в городе или возит туда, поэтому город
   меняет и состав списка), фильтры «есть цена», «есть контакты», «есть документы» (декларации в реестре или на
   сайте), тип компании по ОКВЭД (опт, производители, розница); у каждого — число подходящих.
   Над таблицей — поиск по названию и товару: «форель», «моцарелла». Выгрузка XLSX называется по выборке:
   «Поставщики_Лосось и форель_Тюмень_2026-10-29.xlsx».
2. **Ведомость** — рейтинг 0–100 и табло из восьми огоньков: какие факты найдены с источником (цена, мин. заказ,
   доставка, документы, телефон, email, ИНН, ЕГРЮЛ), а какие станут вопросами в запросе КП. Условия доставки,
   контакты; карточка раскрывается прямо в строке.
3. **Карточка** — слева факты по разделам (условия, документы, юрлицо, контакты): у каждого условия цитата,
   ссылка на страницу-источник и дата сбора, пробел помечен «спросим в КП». Справа действия: письмо КП,
   шортлист, статус, заметка, ответ поставщика и разбор рейтинга.
4. **Сравнение** 2–4 поставщиков бок о бок.
5. **Шортлист**: отметить галочками в выдаче и добавить разом или из карточки; статус (написали / КП получено /
   договариваемся / отказ), заметки.
6. **Запрос КП** — письмо собирается из пробелов в карточке: нет цены — просим прайс, нет документов — спрашиваем
   декларации и ветсвидетельства. Открывается в почте одной кнопкой.
   **Ответ на КП** закупщик вносит в карточку (цена, мин. заказ, доставка, документы): это факт с пометкой
   «ответ на КП» — зажигает огонёк, даёт баллы рейтинга и убирает вопрос из письма. Так база пополняется работой
   закупщика, а не только сбором.
7. **Живой поиск** — под выдачей: «Найти новых в Яндексе» ищет сайты поставщиков по категории и городу, обходит
   их и проверяет ИНН, около 1–3 минут. Каждая пара «категория + город» — раз в день, всего до 10 запусков в день
   (`LIVE_LIMIT`): запросы к Yandex Search API платные.
8. **Поставщики в ИИ-ассистенте (MCP)** — те же поиск, карточка с цитатами и письмо КП доступны любому ИИ-агенту
   с поддержкой MCP (Claude, ChatGPT, Cursor и др.): «найди трёх поставщиков моцареллы в Тюмени с доставкой и подготовь письма».

## MCP: поставщики в ИИ-агенте

Адрес: **`https://suppliers.alexmedvedev.com/mcp`** (Streamable HTTP, без авторизации, только чтение).

| Инструмент | Что делает |
|---|---|
| `list_categories` | категории по группам, сети и их города, фильтры |
| `search_suppliers` | поставщики категории в городе (география: местные, возят в город, все) с рейтингом, условиями, контактами и тем, что спросить в КП |
| `get_supplier` | карточка: каждый факт с цитатой, ссылкой и датой, разбор рейтинга, юрлицо по ЕГРЮЛ |
| `draft_rfq` | письмо-запрос КП из пробелов в карточке и ссылка «открыть в почте» |

Подключение — адрес выше как удалённый MCP-сервер (HTTP) в любом клиенте. Claude.ai: Settings → Connectors →
Add custom connector; Claude Code:
`claude mcp add --transport http suppliers https://suppliers.alexmedvedev.com/mcp` (`-s user` — во всех проектах).

Ядро по-прежнему без LLM: модель — только интерфейс, факты и рейтинг считает тот же код, что и сайт, поэтому
ассистент не выдумывает цену или условия, а цитирует источник или предлагает спросить в КП. Шортлист и заметки
остаются в веб-интерфейсе: публичный сервер без авторизации не должен менять общие данные.

## Что собрано (29.10.2026: Екатеринбург, Тюмень, Челябинск, Уфа)

- **1177 поставщиков по 16 категориям**: 400 найдены через Яндекс в городах сетей (сайты), 783 — производители
  из рубрик productcenter.ru (у части поставщиков оба источника).
- **Заполненность полей** (считаются только разобранные значения: доставка — признаки вроде «по городу» или
  «бесплатно от 5 000 ₽», а не упоминание слова; мин. заказ — число с единицей; цена — только товар категории):

  | Поле | Заполнено |
  |---|---|
  | телефон или email | 94% |
  | email | 91% |
  | телефон | 80% |
  | ИНН | 59% |
  | действующее юрлицо по ЕГРЮЛ | 54% |
  | документы: действующие декларации в реестре Росаккредитации или упоминание на сайте | 41% |
  | — из них действующие декларации в реестре | 25% |
  | условия доставки | 34% |
  | минимальный заказ | 5% |
  | цена товара категории (с сайта или из прайс-листа) | 1,4% |
  | ссылка на прайс-лист | 3% |

- **Каждая цитата подтверждает своё значение**: в фактах из текста сайтов число цены, мин. заказа и ИНН есть
  в цитате-источнике у 100% (проверка по всей базе после пересборки). У цен из прайс-листов источник — сам файл,
  у деклараций — карточка в реестре, у ответа на КП — пометка закупщика.
- **Точность выдачи**: в топ-10 четырёх категорий (лосось и форель, рис, сыры, упаковка; Екатеринбург) 31 из 40 —
  профильные B2B-поставщики, 8 спорные (опт вместе с розницей, оптовый агрегатор, упаковка не для доставки), 1 мимо.
  Проверка по главным страницам сайтов и ОКВЭД, 29.10.2026. До минус-слов категорий и штрафа за «доставку на дом»
  было 28 из 40.
- **Вывод.** Контакты, юрлицо и декларации собираются автоматически у большинства. Цену и минимальный заказ
  публикуют единицы — даже из 232 разобранных позиций прайс-листов к категории поставщика подошли единицы.
  Эти пробелы закрывает письмо-запрос КП и ответ поставщика, который закупщик вносит в карточку, а не догадки модели.

## Как работает

```
категория + город
  → запросы и ключевые слова категории (categories.yaml)
  → кандидаты: Yandex Search API (регион города) + рубрики productcenter.ru
  → склейка дублей по ИНН / домену
  → обход сайта: главная + до 6 страниц (сначала доставка и оплата, затем опт и прайс, контакты, документы,
    о компании) + страница каталога, ссылки на прайсы; сырые ответы кэшируются в data/cache
  → прайс-листы XLSX, XLS, PDF (до 3 на сайт): колонки по заголовку таблицы, оптовая цена, если есть;
    товар — по первым словам позиции, до 5 позиций на категорию; из шапки прайса — ИНН, телефон, email
  → основной контент страницы без меню и футера (trafilatura, алгоритм класса Readability)
  → извлечение фактов правилами (core.extract): со всей страницы — ИНН с контрольной суммой, телефоны, email,
    география; из основного контента — цена за кг/шт, минимальный заказ (число с единицей), условия доставки
    (по городу / области / России, самовывоз, через ТК, бесплатно от N ₽), упоминания документов
  → ЕГРЮЛ через DaData: статус, возраст, ОКВЭД, адрес; юрназвание вместо домена
  → реестр деклараций Росаккредитации (открытые данные, ~15 ГБ JSONL в 7z, поток): действующие декларации, где
    изготовитель — наш поставщик; в наборе нет ИНН, поэтому сверка по юрназванию из ЕГРЮЛ и региону адреса
  → рейтинг (core.score) считается при каждом запросе под выбранные категорию и город;
    цена засчитывается, только если рядом назван товар категории
```

**Рейтинг, 100 баллов.** Ранжирует, насколько поставщик подходит. Баллы даются только за разобранные значения:
упоминание доставки без условий или «минимальный заказ?» без числа не считаются.

| Блок | Баллы | Что даёт баллы |
|---|---|---|
| Релевантность | до 30 | предложение в рубрике каталога; категория на сайте и опт/HoReCa; −20, если похоже на ресторан |
| География | 20 | находится или работает в городе/области; 10 — город только в списке зоны доставки или «доставка по России» |
| Контакты | 10 | телефон, email |
| Условия | 10 | цена товара категории, минимальный заказ, условия доставки |
| Надёжность | до 25 | ИНН, действующее юрлицо, на рынке от 3 лет, ОКВЭД опта или производства; −10 за розницу и −20 за общепит по ОКВЭД |
| Документы | 5 | действующие декларации в реестре Росаккредитации; если их нет — упоминание деклараций, ветдокументов, ХАССП, ГОСТ на сайте |

## Почему так

- **Веб-приложение.** Закупщику нужны таблица, сравнение и карточка с источниками. В Telegram-боте это не
  помещается, Streamlit выглядит как админка. Работает по ссылке, ничего не нужно ставить.
- **Ядро без LLM.** Извлечение и рейтинг сделаны на правилах: они воспроизводимы, объяснимы закупщику («почему
  этот первый») и не падают, если внешняя модель недоступна. Нейросети использовались при разработке: анализ
  задания, разведка источников, код, тесты. LLM-проход (YandexGPT) стоит добавлять один раз на этапе сбора и только
  для свободного текста, где правила проседают, с обязательной цитатой-доказательством.
- **Каждый факт — с источником.** «Полнота» без проверяемости ничего не стоит. Пробел честно помечается
  «не найдено» и превращается в вопрос в письме КП.
- **Честный сбор.** robots.txt, паузы, User-Agent бота с адресом страницы «Как это работает». Капчу и
  антибот-защиту не обходим: Пульс цен и agroserver.ru закрыты для ботов, поэтому их пропускаем. HTML карт
  (2ГИС, Яндекс.Карты) не парсим, только API. Частных лиц не собираем.

## Запуск

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
python test_core.py                                # проверки извлечения и рейтинга
YANDEX_API_KEY=… YANDEX_FOLDER_ID=… DADATA_TOKEN=… python collect.py seed --pages 2   # сбор, нужен российский IP
uvicorn app:app --port 8766
```

Декларации из реестра Росаккредитации: скачать `rds-full.7z` с fsa.gov.ru/opendata в `data/fsa/`, затем
`python collect.py fsa` (нужен 7z; около 15 минут, читает архив потоком).

Дообойти сайты новыми правилами (страница каталога, прайсы) в текущей базе: `python collect.py sites --again` —
страницы из кэша, факты только добавляются.

Пересборка базы новыми правилами: `SUPPLIERS_DB=data/rebuild.sqlite python collect.py rebuild --pages 2`
(все города сетей, потом каталоги, по очереди), проверить и подменить `data/suppliers.sqlite`. Страницы и
ответы Яндекса и DaData берутся из `data/cache`, поэтому повторный обход и платные запросы не нужны. Свежие данные —
удалить и `data/cache`.

Деплой: `deploy/install.sh`, systemd + Caddy.

| Файл | Что внутри |
|---|---|
| `categories.yaml` | дерево категорий: сети, ключевые слова, запросы, рубрики |
| `core.py` | извлечение фактов, рейтинг, хранилище SQLite |
| `collect.py` | сборщики источников, обход сайтов, DaData |
| `app.py`, `templates/` | интерфейс |
| `test_core.py` | проверки на реальных текстах |
| `test_mcp.py` | проверка MCP-сервера настоящим клиентом: `python test_mcp.py https://…/mcp` |

## Ограничения и что дальше

- Цены и минимальный заказ публикует меньшинство поставщиков: остальное закрывает письмо КП.
- Прайс-листы разбираются, если они таблицей с заголовком или PDF с ценой в рублях в строке; сканы и картинки — нет.
- Шортлист, заметки и ответы на КП общие для всех посетителей: это демо, авторизации нет.
- Декларации находятся только у производителей: в открытых данных Росаккредитации нет заявителя и ИНН, поэтому
  дистрибьюторов и импортёров по реестру не сверить.
- Дальше: LLM-проход по свободному тексту, платный 2GIS для
  телефонов точек, передача выбранного поставщика в складской модуль Goulash (тот же MCP-сервер — точка
  интеграции), шортлист через MCP с авторизацией.
