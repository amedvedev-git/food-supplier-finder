# Аудит подхода и логики сбора — 2026-10-29

Предмет аудита: `collect.py`, `core.py`, `categories.yaml`, база `data/suppliers.sqlite` (327 поставщиков,
сбор 29.10 08:07–08:26) и сверка с заданием из PDF. Каждый вывод ниже проверен запросом к базе или прогоном
кода, а не только чтением.

## Вывод

Каркас подхода сильный, его стоит сохранить: каждый факт с источником, прозрачный рейтинг, вежливый сбор,
проверка юрлица, ядро без внешних зависимостей. Слабые места — в трёх местах:

1. **База не соответствует коду.** Больше половины цитат не содержат значения, которое должны подтверждать.
   Это бьёт по главному принципу сервиса.
2. **Свободный текст (доставка, мин. заказ, привязка цены к товару) правила не вытягивают.** По собственному
   правилу плана («LLM — если замер покажет провал правил») LLM-проход уже оправдан.
3. **Сигнал, который отсеивает розницу, уже собран, но не используется:** ОКВЭД из ЕГРЮЛ.

## Что сделано правильно (не трогать)

- **Факт = значение + цитата + URL + дата.** Это правильная модель данных, на ней держится доверие.
- **Рейтинг объясним по пунктам**, «не найдено» превращается в вопрос в письме КП. Это сильная продуктовая
  связка.
- **ИНН проверяется по контрольной сумме**, дальше DaData. Склейка дублей по ИНН и домену. Если на сайте
  несколько ИНН, записи не склеиваются — это аккуратно.
- **robots.txt, пауза на хост, честный User-Agent**, отказ от обхода капчи. Для публичного демо это плюс.
- **Тесты на реальных кусках текста**, включая регрессию «Богишамол» (`test_core.py:51`).

## Находки

### A. Воспроизводимость данных — P0

**A1. База собрана старой версией экстрактора.** Текущий `_win` / `_cut` (`core.py:105`) ставит значение внутрь
цитаты: синтетический тест это подтверждает, и `test_core.py:59` проверяет ровно случай «Богишамол». В базе же
цитаты выглядят как «первые ~200 символов предложения…». Пример: цена «1089.62 ₽/кг» подтверждается цитатой,
где стоит «1158.13 ₽/кг». В UI это видно как «29 900 ₽/кг» у лосося с цитатой без этого числа. Проверяющий,
который кликнет по источнику, увидит, что факт им не подтверждается.

**A2. Пересобрать базу «просто перезапуском» нельзя.**
- `facts` пишутся через `insert or ignore` с ключом `(supplier, field, value)`: старые значения остаются, новые
  добавляются рядом.
- Сайт, однажды попавший в `pages`, больше никогда не обходится (`enrich_sites`, `site not in pages`).
- Повторный `seed` поверх текущей базы ничего не исправит, нужна чистая база.

**A3. Сырые страницы не сохраняются.** Любое улучшение правил требует нового обхода сайтов (30–60 минут
трафика). Оценить качество офлайн тоже нельзя: «поменял регулярку → сравнил точность до и после».
Стандартный приём — хранить текст страниц (сжатый: ~300 сайтов × 5 страниц ≈ десятки МБ) и иметь команду
`collect.py reextract`, которая пересчитывает `facts` из сохранённого текста.

### B. Извлечение фактов

**B1. «Доставка» — это упоминание, а не условие (P0).** Значение — окно в 140 символов вокруг слова «доставк»
(`core.py:145`). Цифра README «условия доставки 65%» на самом деле означает «на сайте есть слово доставка».
Это вводит в заблуждение. Нужны признаки: зоны (город / область / РФ), порог бесплатной доставки, график,
самовывоз.

**B2. Цена не привязана к товару и категории (P0).** Регулярка берёт любую цену со страницы, поэтому у
поставщика лосося лежат цены каракатиц из прайса. Цена должна относиться к предложению: товар, категория,
единица. Минимум без LLM — принимать цену, только если в её окне есть ключевое слово категории, и проверять
правдоподобный диапазон для категории.

**B3. Весь `<body>` — источник шума (P1).** Меню, футер и список филиалов попадают в те же «предложения»
(«Каталог Контакты О компании Интересное Обзоры…»), отсюда 38 телефонов и мусор в доставке. Условия лучше
извлекать из основного контента (удалить `header`, `nav`, `footer` или взять trafilatura), а контакты — со всей
страницы: они как раз часто в футере. Основной телефон — с кодом региона поставщика, остальные — «ещё».

**B4. Документы засчитываются по упоминанию слова (P1).** Метка «Меркурий» ставится по слову «ветеринарн»
где угодно, «ГОСТ» — по любому упоминанию. Это даёт 10 баллов из 100 за слово на странице. Реальная проверка
делается по ИНН в реестрах:
- **ФСА** (pub.fsa.gov.ru) — декларации и сертификаты;
- **Цербер / ФГИС «Меркурий»** — поднадзорное предприятие, критично для рыбы, мяса и молока.

Пока проверки нет, нужна честная подпись: «упоминается на сайте», а не «есть документы».

**B5. Название и город (P1).** 36% названий — домены, хотя у 150 поставщиков есть юрназвание из DaData
(`name.short_with_opf`). Порядок fallback: og:site_name → `pick_name` → короткое юрназвание → домен.
`enrich_sites` безусловно перезаписывает имя (`collect.py:233`), в том числе хорошее имя из productcenter.

### C. Поиск кандидатов и релевантность

**C1. ОКВЭД собран, но не используется (P0, ~5 строк).** README сам называет главную ошибку — «розничные
магазины с доставкой», а лекарство уже лежит в `legal.okved`. Предлагаемая шкала:
- 46.x (опт) и 10.x (производство) — плюс;
- 47.x (розница) и 56.x (общепит) — минус и пометка «розница».

Жёстко отсекать не нужно: у части оптовиков основной ОКВЭД 47.91. Нужен сигнал с весом и видимая плашка.

**C2. Город в UI шире, чем данные (P1).** Сбор шёл по Екатеринбургу, а в выпадающем списке 11 городов. В
Тюмени «Лосось» показывает тех же екатеринбургских поставщиков, у «Кристалл Фиш» снова 98. Варианты:
оставить в списке только города, по которым был сбор, или досеять города сетей (`NET_CITIES`: Тюмень,
Челябинск, Уфа) — это ~0,5 ₽ за запрос.

**C3. Полнота поиска не измерена (P2).** Запрос берёт 2 формулировки × 20 результатов × 1 страницу Яндекса
на категорию, после фильтра `SKIP` остаётся ~25 поставщиков. Точность топ-10 (36 из 40) проверял автор,
полноту не мерили никак. Дешёвая проверка: 5 известных поставщиков Екатеринбурга по лососю — нашёл ли их
сервис?

**C4. Широкие дистрибьюторы (P2, идея).** GFC-Russia закрывает 16 категорий, marr.ru — 12. Для закупщика это
плюс: меньше контрагентов. Стоит показывать «закрывает N категорий вашей сети».

### D. Рейтинг

**D1. Рейтинг смешивает «подходит ли поставщик» и «сколько мы о нём знаем» (P1).** 23 балла «полноты» дают за
то, что на сайте есть цена, мин. заказ и доставка. Значит, выше поднимаются поставщики с хорошим SEO-сайтом,
а не лучшие поставщики. Отсутствие цены на сайте — пробел наших данных, а не минус поставщика: его закрывает
письмо КП. Предложение:
- ранжировать по «подходит»: категория, B2B по ОКВЭД, регион, живое юрлицо, есть контакт;
- полноту показывать отдельной шкалой «знаем 4 из 7».

Заодно уйдут ничьи вида «шесть поставщиков по 83».

**D2. Баллы начисляются за невалидированные факты.** +5 за «доставку»-упоминание, +5 за мусорный мин. заказ,
+10 за слово «ГОСТ». После B1–B4 баллы стоит давать только за нормализованные значения.

### E. Роль AI — главный стратегический риск

Задание — на позицию **AI Generalist / AI Automation Specialist**, HR прямо просил «нейронки на всех этапах».
В продукте сейчас LLM нет совсем: README объясняет, что нейросети использовались при разработке. Аргумент
«правила воспроизводимы и объяснимы» верный для ИНН, телефонов и email. Но собственный план ставил условие
«LLM — если замер покажет провал правил», и замер это показал: доставка (B1), привязка цены (B2), мин. заказ,
названия (B5), отличие опта от розницы (C1).

Гибрид, который не ломает принципы сервиса:
- **Правила остаются** для ИНН, телефонов, email и ЕГРЮЛ: там они точнее модели.
- **Один LLM-проход при сборе**, не в рантайме. На вход — основной текст 2–5 страниц поставщика. На выход —
  JSON по схеме: `is_b2b`, `supplier_type`, `categories`, `delivery{zones, free_from, schedule, pickup}`,
  `moq{value, unit}`, `prices[{product, category, value, unit}]`, `company_name`. **У каждого поля — дословная
  цитата.**
- **Валидатор вместо доверия.** Цитата должна быть подстрокой сохранённого текста, число из значения должно
  встречаться в цитате. Иначе поле отбрасывается. Так галлюцинация невозможна по построению, а принцип
  «каждый факт с источником» усиливается.
- **Стоимость.** ~327 поставщиков × ~6 тыс. токенов ≈ 2 млн токенов, YandexGPT Lite — около 400 ₽ (по ценам из
  плана).
- **Доказательство эффекта.** Размеченный эталон на 30 поставщиков, точность по полям «правила» против
  «правила + LLM». Одна такая таблица в README сильнее любого абзаца про подход.

Это меняет архитектурное решение из плана, поэтому решение за вами.

### F. Эксплуатация (P2)
- **`JOB` — глобальная переменная процесса.** Работает только при одном воркере uvicorn (так сейчас и
  настроено в `deploy/suppliers.service`). При `--workers 2` живой поиск сломается молча.
- **Нет расписания пересбора.** `suppliers-collect.service` разовый, а дата у факта — это дата первой записи,
  её никто не обновляет.
- **`merge()` переносит keys, offers, facts и marks**, но не поля самой записи. Если у удаляемого дубля был
  ЕГРЮЛ, а у оставшегося нет, результат DaData теряется.
- **Ключи DaData и Yandex Cloud** лежат открытым текстом в `suppliers.md` в корне. В git файл не попадает, но
  его стоит перенести в `.env`.

## Аналоги подхода

| Аналог | Как устроен | Что взять |
|---|---|---|
| **Diffbot, Zyte AutoExtract** | Обход → отделение основного контента от шаблона → ML-извлечение с оценкой уверенности | Очистка от меню и футера до извлечения; уверенность у факта |
| **Firecrawl / Jina Reader + LLM extract** | Страница → чистый markdown → извлечение по JSON-схеме | Ровно тот гибрид, что предложен в разделе E |
| **Elicit** | LLM извлекает факт и обязательно приводит подтверждающую цитату | Цитата как жёсткое требование валидатора, а не украшение |
| **Контур.Фокус / СПАРК** | Не парсят сайты, а сводят госреестры по ИНН | ОКВЭД, ФСА, Меркурий, арбитраж — сигналы надёжности сильнее текста сайта |
| **ЕИС «Закупки» (44/223-ФЗ, открытые данные)** | Контракты на поставку продуктов школам, больницам, госкомпаниям с ценой за единицу | Новый источник: кто реально поставляет лосось в Свердловской области и по какой цене. Это доказанный B2B и настоящие цены — то, чего на сайтах нет у 91% |

## Поправка к README после пересборки

Нужно либо переименовать строки («упоминание доставки на сайте»), либо считать только нормализованные
значения. Убрать «телефону» из описания склейки дублей или реализовать её.
